# Technical publication graphics

Use when technical illustrations become multi-step instructions, service sheets, parts catalogs, assembly guides or other structured publications.

- Define the reader task first: assemble, service, identify parts, inspect dimensions or understand a process.
- Keep the source model/revision and parts/BOM identity attached to every derived view and page.
- Break procedures into one clear action/decision per step where practical; do not compress several assembly states into one ambiguous illustration.
- Keep view orientation, projection convention and callout numbering consistent across pages so the reader does not mentally remap the product each step.
- Use exploded spacing to communicate sequence and relationship, not to create a decorative 'explosion'.
- Pair callouts with the authoritative parts list and detect missing, duplicated or orphaned identifiers before publication.
- Separate explanatory dimensions from manufacturing dimensions; never imply scale/measurement authority where the page is only illustrative.
- Use section/detail views only when they answer a specific ambiguity that the main view cannot.
- Preserve editable vector/linked output when future revisions are expected, then hand final print/PDF packaging to the existing prepress authority.
- For HTML5/XVL derivatives, verify that model/view navigation and package files correspond to the same accepted source revision as the PDF/CDR publication.
