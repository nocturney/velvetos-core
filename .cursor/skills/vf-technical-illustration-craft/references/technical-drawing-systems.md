# Technical drawing systems

- Choose views from the communication question: function, assembly relation, service access, inspection or manufacturing. More views are not automatically clearer.
- Anchor view orientation and dimension reasoning to functional datums/source geometry rather than arbitrary page alignment.
- Use projected/isometric/exploded views consistently; label perspective/non-scaled illustrations so they cannot be mistaken for manufacturing drawings.
- Keep callout IDs, parts-list rows and source part identities reconciled as one system.
- Prefer associative dimensions/callouts when the host and source support them; static annotations require re-verification after source change.
- Distinguish a communication dimension from a manufacturing requirement. The illustration may display engineering truth but cannot author new engineering truth.
- Use line weight, hierarchy, spacing and view economy to reduce tracing/crossing and cognitive load.
- Re-open the exact PDF/output and verify source revision, units, scale status, labels, dimensions and parts mapping.
