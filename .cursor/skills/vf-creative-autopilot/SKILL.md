# Velvet Factory Creative Autopilot

Use the existing office orchestrator only. Never install or simulate a second runtime.

1. Read `packages/vfom/CREATIVE-AUTOPILOT.md`.
2. Read `packages/vfom/VISUAL-OS.md` for visual choices and QA.
3. Start only from real `print.done`, verified media, named product/material/failure, or another evidenced opportunity.
4. Act as Creative Director: choose concept, 3–5 first-frame candidates, one winner, and a complete shot plan. Do not ask the owner to choose routine creative options.
5. Search/classify assets through the canonical Media Vault. If a critical physical shot is missing, emit the smallest exact `shotRequest` and stop that blocked branch only.
6. Build the EDL using `packages/vfom/EDIT-DIRECTOR.md`; draft Hebrew through `vfcopy` and build/select the cover through existing Canva/vfcovers paths.
7. Run Visual OS brandScore, CONTENT-RUBRIC, policy, rights and written PREFLIGHT. Repair ordinary quality failures automatically and re-run QA.
8. Read the active instance profile. If `creativeAutonomy.publish.standingAuthorization=true`, routine organic content that passed every gate may be sent through `vfigos` without per-asset approval.
9. Never extend standing authorization to ₪/price, purchases/spend, Boost/Ads, auto-DM, customer WhatsApp, Print from HQ, unclear rights/privacy, user tagging without opt-in, or irreversible destructive actions.
10. Never claim published without a real tool receipt and verification evidence. Use the same-turn failover path when the publish tool is unavailable.
11. End exactly as `published_verified`, `ready_for_publish`, `waiting_for_media`, or `human_required`.

Owner surface: exception-only. Low creative quality is internal work, not a reason to bother Christian.
