### Four independent native scenarios (47/47 PASS, twice)

1. **Normal signed request:** Root-only fixture issues actual 90-second etcd lease attached to one exact synthetic owner. UID62005 signs scope bytes under its own 0600 Ed25519 private key; kernel-identified UID62002 cannot read signer key, private sink TLS key, sink Git or fake local credential. Sink UID62001 validates Ed25519, `SO_PEERCRED`, source/host/worker/ref/action/expiry and uses its own real mTLS cert to read owner+lease+exact mod_revision. One real etcd `txn` atomically compares that owner revision plus `version(intent)=0` to create an unleased `EFFECT_IN_FLIGHT` intent. **The sink then checks current live provider status immediately before its actual local Git CAS** and emits only one native `git update-ref`. Root test controller subsequently reconciles the exact owner/intent revisions to `VERIFIED_LOCAL_ONLY` after native Git ref readback. Duplicate exact signed request is refused.
2. **Actual revocation between pending and effect:** After durable etcd pending intent but **before last real provider check**, root-controller deletes the leased owner key. Sink resumes only after explicit fixture barrier and refuses to mutate the local Git ref. Pending remains unleased; a new owner cannot atomically ignore `version(intent)!=0`.
3. **Actual natural TTL expiry:** A separate 2-second real etcd lease expires with pending durable but before the local Git effect. Sink's last provider read sees absent owner, refuses; no local ref changed; new-epoch owner bypass is denied.
4. **Actual lost ACK after native Git:** Third independent scenario completes one validated local Git CAS but the privileged sink dies before client ACK/SQLite terminal receipt. Signed worker observes `NO_ACK_UNKNOWN`; sink restart freezes durable SQLite `FROZEN_UNKNOWN`; valid signed replay refused; etcd retains unleased `EFFECT_IN_FLIGHT` to require independent investigation rather than blind retry.

Each scenario additionally validates issuer-only owner mutation, worker/outsider RBAC, separate UID ownership and worker/signer inability to read the mTLS sink client key. All test-only signer and provider certs, WALs, Unix sockets and bare Git ref fixtures are destroyed by the individual TemporaryDirectory context after each full test.

## Explicit gaps — still RED; do not promote

- **TOCTOU race:** The last real etcd owner/intention read and `git update-ref` are different systems. There is a nonzero window for an owner to expire/revoke AFTER check but BEFORE effect. This experiment proves refusal when revoked/expired **before** check, **not atomic effect-time or transactionally fenced GitHub push**. Provider→Git or provider→GitHub cross-store atomicity remains unproven.
