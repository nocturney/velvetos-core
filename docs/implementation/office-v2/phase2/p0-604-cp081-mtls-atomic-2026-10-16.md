**2026-10-16 | Office #604 / #612 | merged into main via #758 (6cec8e86); lab-only, SECURITY RED**

## What changed beyond CP077 and CP080

- CP077 exercised genuine mTLS/RBAC and separately privileged OS UIDs, but exposed a real provider-to-native-local-Git TOCTOU gap after its final check.
- CP080 tested issuer-committed multi-key atomic admit/revoke and competing real etcd transactions, but used unauthenticated loopback HTTP without RBAC.
- **CP081 tests authentic mTLS certificate identities, scoped RBAC and CP080-style multi-key transactions together in one fresh rootless etcd 3.6.15 instance**. This narrows one integration gap only; it does **not** combine CP077's separate-UID Git-writing sink or any remote GitHub operation.

## Negative and positive checks

- An authorized synthetic issuer pins the exact leased owner `mod_revision` before attempting an atomic transaction. Duplicate admission, admission after committed revoke and same-value-but-recreated-owner ABA all fail closed.
- A separate mTLS sink CN can read owner/generation/ref and manage *only* its own intent. Worker CN can read owner only. Worker intent writes, sink owner mutation and outsider ownership reads are rejected by real etcd RBAC.
- An admission-first transaction reserves intent/task/host/GPU/ref together. A later revoke requests draining while leaving pending intent/ref reserved; TTL expiry does not erase this unleased pending work.
- Root issuer's concurrent `admit` and `revoke` transactions race against the same genuine etcd key revision and cannot both win.
- The canonical CI follow-up uses **only** `--selftest`: no TLS key generation, no etcd service, no network, no Git, no production credentials or machine-user state.

## Hard boundary and next proof

**Do not merge or enable a privileged GitHub sink based on this fixture.** The issuer is a self-contained synthetic test root, not protected Core. The authenticated client role is **not yet an OS-separated credential sink** in the same CP081 execution. There is **no GitHub remote**, network-request completion proof, lost-ACK reconciliation, cross-store atomic provider-to-Git effect, real owner-approved Option A/B semantics, two physical-host guarded model-code execution, or independent security signoff.

The explicit CP077 adversarial late-revoke local-Git witness remains an unresolved security issue. A future controlled test must join this issuer grant to one separately privileged *real* sink and explicit remote uncertain-outcome handling; it must not equate etcd atomic admission with atomicity of a later GitHub write. `P0_GENERATED_SOURCE_OS_ISOLATION_NOT_ADMITTED` remains enforced.
