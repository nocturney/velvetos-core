# CP078-R2 — finite abstract interleaving exploration (isolated, evidence only)

**2026-10-15 | OFFICE #604 / #612 | Internal abstract model check | P0 SECURITY ADMISSION RED**

## Why this exists

CP077 [Draft PR #730](https://github.com/nocturney/velvetos-core/pull/730) reproduced a **real unsafe** stale local Git ref effect when an etcd owner was revoked between the sink's last provider read and `git update-ref`. CP078-R1 documents the candidate revised protocol and 70 *data-only unexecuted* adversarial schedules. The isolated exercise below turns a deliberately **small abstract version** of its Option A revocation semantics into enumerated state transitions; it does **not** run etcd, GitHub, native Git, source generated by a coding model, or privileged production code.

**Scope warning:** This is a model authored and run inside the assistant's isolated sandbox, *not* an independently reviewed formal specification and *not* a native provider validation. Neither the correctness of the abstraction nor its correspondence to real implementations has been independently verified.

## Abstract model and exploration

One issuer generation, one intent, one repo/ref, one abstract Git remote request and one successor. Issuer state separates `ACTIVE`, `SUBMITTED` (UI click), `COMMITTED` (issuer-quorum revoke), `EFFECTIVE`. Effect state has `PREPARED`, `ADMITTED`, `IN_FLIGHT`, `UNKNOWN`, `VERIFIED_EFFECT`, `VERIFIED_NO_EFFECT`. Delivery is nondeterministic and may land after timeout; admissibility is serialized against issuer-committed revoke, and effective revoke is delayed until no possibly late remote request remains. No automatic retry. This is a *finite state abstraction*, not source code execution of the P0 agent.

Python-standard-library, bounded-state explicit exploration: breadth-first traversal for shortest violation traces, cross-checked with a depth-first reachable-state count using the same transition function. The full reachable graph was exhausted at max shortest trace length 9, within depth budget 20; the explorer reported no depth truncation. The checker was run **only in the assistant's disposable sandbox** and is provided separately to the user in an exact-checksum evidence ZIP. No program or code produced during this R2 exercise was run on any user-connected workstation, Colima guest or GitHub runner.

### Two IMPORTANT explicit counterexamples to strict click-time Option B

1. `prepare_intent → ui_submit_revoke → atomic_commit_admitted → fsync_send_start_then_dispatch → destination_applies_exact_ref`: the effect occurs after the UI click because that click was not yet issuer-committed.
2. `prepare_intent → ui_submit_revoke → atomic_commit_admitted → issuer_commit_revoke → fsync_send_start_then_dispatch → destination_applies_exact_ref`: an **already-admitted** effect can even land after the revoke request is committed under proposed Option A. The effective revoke ACK is still prohibited until this effect is terminal.

These are **expected consequences of Option A**, and critical reasons the owner must not be told it guarantees immediate no-effect after a revoke request.

### Minimum baseline CP077 unsafe-witness trace

`ui_submit_revoke → old_final_etcd_owner_read → issuer_commit_revoke → BUG_git_update_after_etcd_revoke`

This *abstract* trace resembles the **already observed** CP077 native etcd/local-Git failure, but it is not a new native replication. The original CP077 real observation remains a separate historical receipt.

### Eight abstract assertions

- No `COMMIT_ADMITTED` granted after authoritative committed revoke for the same generation.
- No `REVOKED_EFFECTIVE` while an admitted remote send may still be in flight.
- No delivery of a system-owned ref update after effective revoke is acknowledged.
- No successor allowed while previous generation is pending/unknown.
- No more than one locally dispatched request for the same unique intent.
- No more than one remote effect per abstract intent.
- No ref effect without prior serialized grant.
- No `VERIFIED_NO_EFFECT` while send remains queued or has been applied.
