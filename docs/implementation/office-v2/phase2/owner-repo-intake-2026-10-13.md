## Execution order: no new scheduler or speculative ownership

1. **P0 FIRST (#612):** preserve the already-running/queued OpenCode/local inference baseline and prove one real independently tested coding-task PR, then two-host PR/QA/crash-resume. New agent executors are **queued only** until this baseline is trustworthy. Codex CLI remains prohibited by owner quota decision; no new recurring inference purchases.
2. **Agent-runtime fair comparison:** after baseline/available independent capacity and specific admission, compare Reasonix, Code Puppy, Qwen Code, Kilo Code, OpenRig, Yao, ANUS, Ouroboros and Aetox against the same envelope (identical synthetic repo/task, base SHA, model/provider permission, sandbox, duration, memory, correct tests, PR/CI, independent QA and receipts). Do not install all nine at once; conduct capacity triage 2-3 challengers at a time, recording queue/reorder evidence. Aetox may be tested as standalone licensed software, never copied or modified.
3. **Context and QA track (#612):** Code Review Graph vs Serena vs existing search/LSP; test symbol/graph accuracy and missed blast-radius, re-index freshness, token consumption. RTK tests compare full diagnostic output to compressed view without suppressing failures or security receipts. Loop Engineering/Gentle AI are controlled workflow-pattern challengers, not an excuse to bypass independent verifier.
4. **Model and resource track (#612):** LlamaFactory only if the same task indicates fine-tuning beats retrieval/prompt engineering, a compliant dataset exists, and spare GPU capacity is proven. Never conflict with LOCAL3D or P0 GPU leases. xxHash benchmarks may optimize *non-security* indexes but SHA-256 remains canonical integrity proof.
5. **UI and control track (#595 / Phase 4):** study Jarvis, Kun and Yao task board for voice, workbench, context and control-center layout; retain approved Control Center design, read-only adapter, unknown/disconnected states and VelvetOS canonical source. Jarvis/Kun commercial-license constraints block code reuse or commercial pilot without permission. STOW remains an independent WPF product with protected tray runtime; do not force Electron migrations.
6. **Creative track (#595 / Phase 6):** test html-video on synthetic licensed images/RTL text and produce reviewable MP4 locally. No Instagram scheduling/publishing or external cloud inference. Evaluate rollback and rights before any live asset processing.
