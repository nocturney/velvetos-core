# no-ai-slop — selective embed into vfcopy

Date: 2026-09-29  
Source: https://github.com/petergyang/no-ai-slop  
License: MIT  
Target: existing `vfcopy` / Visible Text Gate only. No plugin install, no new pack, no new runtime.

## What was useful

The upstream skill contributes a concise named taxonomy for common AI-writing habits, a detect-only workflow that reports evidence instead of guessing authorship, a minimum-effective-edit principle that preserves a writer's voice, and eval-after-edit discipline.

## What VelvetOS embedded

- Named detector in `packages/vfcopy/lint_he.py`: `detect_ai_slop()`.
- High-signal Hebrew/English patterns: binary contrast, throat-clearing, faux insight, colon reveal, superficial analysis, importance puffery, interpretive metadiscourse, weasel attribution, negative listing, rhetorical setup, summary recap and fake-profound ending.
- `python3 scripts/check-vfcopy.py detect --text '…'` → pattern + quote + fix; no score and no AI-authorship claim.
- The same detector runs inside `lint_hebrew_copy()`; it is therefore part of normal lint, not an optional side utility.
- `scripts/vf_visible_text.py` exposes exact anti-slop findings and cannot PASS the Humanizer stage when findings exist.
- Eval cases can declare `expect_patterns`, so CI verifies the specific taxonomy rather than accepting an unrelated generic failure.
- `scripts/check-visible-text-gate.py` contains an end-to-end behavioral assertion: slop fails the exact gate; a concrete clean owner brief can PASS with complete evidence.

## Deliberately not embedded

- No upstream plugin/skill installation.
- No AI-authorship detector or probability score.
- No wholesale English banned-word list imposed on Hebrew.
- No aggressive rewriting that flattens owner/brand voice.
- No second writer or approval queue.

## Operational consequence

A future writer may use detect mode for diagnosis, but final human-visible AI text still goes through the existing pipeline:

truth/context → reader-first → domain/surface writer → velvet-hebrew-copy → lint/Humanizer/anti-slop → factual validation → surface QA → exact-text Visible Text Gate.

A named slop finding blocks `humanizer_ai_tells` and therefore blocks `visible_text_gate: PASS` on that exact candidate.
